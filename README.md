# pair-wise-yf-51 多语言字幕翻译和时间轴协作编辑器

源提示词摘要：制作人建立原语言和多语言字幕轨，译员拆分、合并、移动字幕并维护时间码，审校人员处理术语、超长文本、上下文备注和冲突版本；系统提供术语锁定、审校退回、版本快照、键盘连续操作和导出预览。

## 断网协作 / 凭据重放模型

每台设备的所有改动（编辑、拆分、合并、时间码、审校、术语锁定、冲突裁定）都先写成本机**有序凭据（Credential）**，断网时立即可见；联网后严格按设备序号逐条重放到中心 Hub。

- `src/lib/sync/types.ts` — 凭据 / 冲突两版 / 墓碑 / 审校记录模型
- `src/lib/sync/engine.ts` — 纯函数重放引擎（Hub 重放与本机草稿预演共用）
- `src/lib/sync/hub.ts` — 协作中心（localStorage 模拟服务端）：凭据去重表 + 设备序号
- `src/lib/sync/device.ts` — 设备发件箱、拉取/回传/断点续传、旧数据迁移

关键规则（对应需求）：

1. **按序留凭据、联网逐条重放**：凭据带设备内单调 `seq`，Hub 只按序接收。
2. **目标字幕不在就按时间找回**：凭据携带时间锚点（轨道+起止秒）；对方拆分/合并换了 id 时，按时间重叠/中点距离找回，被合并删除的条目走墓碑恢复。
3. **凭据重复回传只算一次**：Hub 以凭据 id 去重，事件/冲突也由凭据 id 派生，天然幂等。
4. **锁定术语、已通过审校结论不能被重放盖掉**：锁定术语的普通编辑直接拦截并留痕；改已通过字幕的译文/拆分/合并 → 生成两版待判，不覆盖原结论。
5. **两边都改过 → 两版待判**：字幕带每片独立的 `rev` 乐观锁，版本不一致时保留「当前版本/来稿版本」两版，人工裁定后以裁定凭据收敛。
6. **合并失败续传**：重放返回 `retry`（合并对端尚未到达等）时不推进序号、凭据不出箱，下一轮从没做完的凭据接着重试，后续凭据不越过。
7. **旧数据无凭据迁移**：升级时把旧字幕/术语/审校记录/快照打包成一条 `baseline.import` 基线凭据，数据不丢，随后可继续编辑并同步给其他设备（旧审校记录标记为「旧版迁移」）。

演示：顶部「同步中心」可切换两台设备、模拟断网/回网，发件箱实时显示待重放凭据，冲突面板可对两版做 A/B 裁定。

## 技术栈

SvelteKit、TypeScript、Skeleton UI、Svelte stores、TanStack Query、Superforms、Zod、Paraglide。

## 本地运行

```bash
npm install
npm test      # 同步内核端到端测试（9 个场景，覆盖以上全部规则）
npm run check # 类型检查
npm run dev
npm run build
```
